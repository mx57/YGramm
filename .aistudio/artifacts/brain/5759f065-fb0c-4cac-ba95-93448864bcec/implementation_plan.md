# YggGram — Строгая маршрутизация между профилями через сеть Yggdrasil

Исправление архитектуры доставки сообщений, голосовых записей, файлов и звонков между профилями **YggGram**: отказ от скрытой локальной пересылки (`127.0.0.1` / LAN) по умолчанию и перевод всего межпрофильного трафика на **реальную маршрутизацию через внешние публичные узлы Yggdrasil (`0200::/7`)** с автоматическим перебором живых пиров и постановкой в очередь Store-and-Forward (S&F) при отсутствии сети.

---

## 1. Причина проблемы и что изменится

### Что происходило ранее
1. При запуске параллельных профилей метод `syncConcurrentProfileListeners` автоматически прописывал локальный адрес `127.0.0.1:<port>` в таблицу прямых маршрутов `directEndpointTable`.
2. При открытии диалога со вторым профилем (`openChatWithSecondaryProfile`) в параметры чата жестко передавался локальный сокет `127.0.0.1:<allocatedTcpPort>`, а флаг `isLocalLoopbackPeer` обходил проверку наличия интернета и внешних пиров Yggdrasil.
3. В результате пакеты между профилями доставлялись напрямую через локальный сокет в обход оверлейной сети Yggdrasil.

### Новая архитектура маршрутизации
1. **Маршрутизация через внешние узлы Yggdrasil по умолчанию**:
   - Исключается автоматическая привязка `127.0.0.1:<port>` при создании чата между профилями и при синхронизации фоновых профилей. Диалог между профилями создается строго по криптографическому адресу `ygggram://<200::/7 IPv6>?pub=<Ed25519>`.
   - Любое сообщение, голосовая запись, файл или звонок от Профиля №1 к Профилю №2 проходит через метод **`dispatchInterProfileOrMeshMessageViaExternalPeers`**:
     1. Узел отправителя устанавливает реальное TCP/TLS-соединение (с поддержкой SNI / uTLS) к внешнему публичному пиру Yggdrasil.
     2. Выполняет рукопожатие протокола **`YGG_META_v0.5`** и передает зашифрованный фрейм `XChaCha20-Poly1305` (с заголовками отправителя `200::/7` и получателя `200::/7`).
     3. Получает подтверждение от внешнего пира Yggdrasil, замеряет реальный сетевой RTT и фиксирует внешний транзитный узел в журнале пакетов (`TX -> YGG [Внешний пир] -> RX [Профиль]`).
     4. Только после успешного прохождения через внешний узел Yggdrasil пакет передается в сокет целевого профиля, вызывая всплывающее и системное уведомление.

2. **Автоматический перебор живых пиров (Failover) и очередь S&F при отсутствии сети**:
   - Если текущий выбранный пир Yggdrasil не отвечает или отключен, движок автоматически перебирает:
     - Сначала все подключенные пользователем пиры из таблицы маршрутизации;
     - Затем резервные живые публичные пиры из встроенного каталога Yggdrasil (16 стран).
   - Если интернет отключен (или включен Авиарежим), либо ни один внешний пир Yggdrasil недоступен (при выключенном режиме LAN), доставка **не выполняется в обход сети** — сообщение переводится в статус **`QUEUED_OFFLINE_SF`** (очередь Store-and-Forward) до восстановления связи с сетью Yggdrasil.

3. **Ручной переключатель LAN в настройках (По умолчанию ВЫКЛЮЧЕН)**:
   - В `PrivacyMatrixState` параметр `allowDirectLanDiscovery` («Прямая передача по локальной сети LAN / Loopback без внешних пиров Yggdrasil») по умолчанию устанавливается в **`false` (Выключено)**.
   - Пока переключатель выключен, любые локальные маршруты (`127.0.0.1`, `192.168.*`, `10.*`) для межпрофильного обмена заблокированы, и приложение работает исключительно через внешние узлы Yggdrasil.
   - Пользователь может вручную включить переключатель LAN в разделе **«Профиль и Приватность»**, если ему намеренно нужен автономный локальный обмен в изолированной Wi-Fi сети без доступа к интернету.

## 2. Затрагиваемые файлы

- `app/src/main/java/com/example/engine/YggTwinP2PBridge.kt`
  - Удаление авто-регистрации `127.0.0.1` из `directEndpointTable` для фоновых профилей.
  - Реализация `dispatchMessageViaExternalYggdrasilOverlay(...)` с обязательным прохождением через внешний публичный пир Yggdrasil (TCP/TLS + `YGG_META_v0.5`), автоматическим перебором резервных пиров при сбое и доставкой в целевой профиль только после подтверждения от внешнего узла Yggdrasil.
  - Перевод `probeVoiceCallChannel` и `dispatchReactionFrame` на проверку внешнего маршрута Yggdrasil при выключенном тумблере LAN.
- `app/src/main/java/com/example/viewmodel/YggGramViewModel.kt`
  - Установка `allowDirectLanDiscovery = false` по умолчанию в `PrivacyMatrixState`.
  - Обновление `openChatWithSecondaryProfile`, `sendMessage`, `retrySendMessage`, `flushQueuedOfflineMessages` и `startVoiceCall`: строгая маршрутизация между профилями через внешние пиры Yggdrasil, отображение реального внешнего пира-ретранслятора в заголовке чата (`Yggdrasil • <Узел/Страна> (<RTT> мс)`) и постановка в очередь S&F при отсутствии связи с сетью Yggdrasil.
- `app/src/main/java/com/example/ui/screens/ProfilePrivacyScreen.kt`
  - Наглядная индикация режима маршрутизации профилей (`Строго через внешние пиры Yggdrasil 0200::/7` vs `Разрешен ручной LAN-режим`) и обновление описания ручного переключателя LAN.
- `app/src/test/java/com/example/ExampleRobolectricTest.kt`
  - Обновление и добавление тестов, проверяющих, что при отключенной сети и выключенном LAN-переключателе межпрофильные сообщения не обходят сеть через `127.0.0.1`, а ставятся в очередь `QUEUED_OFFLINE_SF`, и доставляются при прохождении через пир Yggdrasil.
